最終更新: 2026-10-26 / ブランチ `claude/eloquent-albattani-lwjtol`（最新コミット `127eff7`、プッシュ済み）

## 1. 目的と前提

- USD/JPY の 3 つのスイング戦略（保有 1〜3 日）を、取引コストを含めて過去データで比較し、
  **統計的な優位性があるかどうか** を検証する。「勝率 90%」は前提にしない。
- MT5 は過去データの取得にのみ使う。**発注機能は実装していない（初期段階では禁止事項）**。
- 禁止事項: 勝率 90% 達成と偽って報告しない／良い期間だけを選んで評価しない／
  バックテスト結果で将来の利益を保証しない。

## 4. 3 つの戦略（判定は H1 足の確定時、約定は次の足の始値）

| 戦略 | トリガー | フィルター（個別に on/off） | 損切り/利確 | 最大保有 |
|---|---|---|---|---|
| 押し目買い・戻り売り `pullback` | H1 RSI が 40 を上抜け（売りは 60 を下抜け） | D1 終値 > SMA50、H4 EMA20 > EMA50、H4 ADX ≥ 20、（H4 MACD は既定 off） | H4 ATR × 1.5 / × 2.0 | 72h |
| レンジブレイクアウト `breakout` | H1 終値が直近 30 本の H4 高値 + 0.1ATR を上抜け | レンジ幅 ≤ 6ATR、H4 ADX ≤ 25、（D1 トレンドは既定 off） | ATR × 1.5 / × 3.0 | 72h |
| 平均回帰 `mean_reversion` | H1 RSI が 30 を上抜け（売りは 70 を下抜け） | H4 ADX < 20、D1 ADX < 25、H4 SMA20 から 1ATR 以上乖離 | ATR × 1.5 / H4 SMA までの距離 | 48h |

各戦略の詳細はソース先頭の説明文と `config/default.yaml` を参照。

## 5. 検証方法とバイアス対策（実装済み）

- **期間分離**: 開発期間 2016–2022 / ホールドアウト（未使用の検証期間）2023–2025。2015 年は指標の助走期間。
- **ウォークフォワード**: 学習 24 か月 → 検証 6 か月、6 か月ずつ移動。パラメーターは学習期間だけで
  27 通りの小さな格子から選び、全検証窓の取引を連結して評価。全窓・全年をレポートに掲載。
- **ホールドアウト**: `--evaluate-holdout` を付けたときだけ評価。評価回数を `results/holdout_log.csv`
  に記録し、2 回目以降はレポートに警告を出す。
- **未来情報の混入防止**: 上位足は確定時刻以降にのみ参照。形成中の足は取得時に破棄。
  期間の境界では強制決済し、期間外の価格を成績に入れない。
- **約定の扱い**: 同じ足で損切りと利確の両方に届いたら損切り扱い。窓開けで損切りを越えたら始値で約定。
- **重複エントリー防止**: 保有中のシグナルは無視、決済後 4 本は新規禁止、同じシグナル ID は 1 回だけ。
- **判定基準**: ウォークフォワードで取引 30 回以上、期待値 > 0、Bonferroni 補正（×3）後の p 値 < 0.05。
  ホールドアウトを評価した場合はそこでも同じ基準を満たすこと。
- **条件別の検証**: 開発期間で、フィルターを 1 つずつ外した／加えたときの成績を出力。

## 6. 次にやること（Windows での実データ検証）

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m pytest                      # 102 件合格を確認
python scripts\fetch_data.py          # 取得 → 自動でデータ検査（異常なら停止）
python scripts\run_backtest.py        # 開発期間で検証（ホールドアウトは見ない）
```

1. MT5 で「ツール → オプション → チャート → チャートの最大バー数」を「無制限」にしておく
   （H1 の 2015 年からの履歴が無いと、データ検査が停止する）。
2. 取得後に `results/data_validation.md` を確認する。タイムゾーン関係で停止したら 7 章を参照。
3. `data/raw/USDJPY_H1.meta.json` の `symbol_info`（業者の現在のスワップ・スプレッド）を見て、
   `config/default.yaml` の直近期間のスワップとスプレッドを合わせる。
4. `results/run_*/report.md` を確認する。ここで設定を変えて試し直すのは開発期間の中だけにする。
5. 戦略・設定を確定してから、**1 回だけ** `python scripts\run_backtest.py --evaluate-holdout` を実行する。

## 7. 業者に合わせて確認する設定（`config/default.yaml`）

| 項目 | 初期値 | 確認すること |
|---|---|---|
| `data.server_timezone` | `NY+7`（冬 GMT+2 / 夏 GMT+3、米国の夏時間に連動） | 欧州の夏時間に連動する業者なら `Europe/Athens` |
| `costs.spread_pips` | 1.2（スタンダード口座） | ECN/RAW 口座なら「RAW スプレッド + 往復手数料の pips 換算」 |
| `costs.use_bar_spread` | true | 足ごとの記録スプレッドとの大きい方を使う |
| `costs.slippage_pips` | 片道 0.3 | — |
| `costs.swap_schedule` | 2015–2025 を 10 期間に分けた概算値 | **推定値であり業者の実績ではない**。直近は業者の値に合わせる |
| `validation.allowed_gap_dates` | 12/24, 12/25, 12/31, 1/1, 聖金曜日 | 他に休場日がある業者なら追加 |
| `validation.expected_daily_bars_per_week` | 5 | 日曜足のある業者（6 本）は日足の意味が変わるので要注意 |

データ検査は「週明けの寄り付きが UTC で日曜夜になっているか」「日足が週 5 本か」を確認し、
合わなければ停止する。

## 8. 開発中に見つけて直した問題（再発防止のため記録）

1. **未来情報の混入をテストが検出できていなかった。** 意図的に 3 通りの混入
   （上位足を開始時刻で結合／1 時間先を参照／未来の終値で RSI）を入れても最初の版のテストは合格した。
   多数の時点で全判定条件を比較する方式に強化し、3 通りとも検出することを確認済み。
   **戦略を追加・変更したら、同じ確認（わざと混入させてテストが落ちること）を行うこと。**
2. **3 か月分の欠落がデータ検査を通っていた。** 長い空白 1 つを「欠損 1 件」と数えていたため。
   欠けた平日の時間数で判定し、1 回 30 時間超で停止するよう修正済み。
3. 終了日を日付で指定すると最終日の足が取得されなかった → その日の終わりまで含めるよう修正済み。

## 9. 合成データでの結果（参考。戦略の評価には使えない）

コストを一般的な水準に設定した後の結果では、3 戦略ともウォークフォワードで「優位性は確認できない」。
最高勝率 42.8%。押し目買い戦略は開発期間の中では p=0.037 と有意に見えたが、
アウトオブサンプルでは p=0.47（コスト変更前の値。過剰適合の典型例）。

## 10. 注意点・既知の制約

- スワップの期間別の値は、政策金利の推移から推定した概算。
- 取引は 1 戦略につき同時に 1 ポジション、固定 1 単位（pips と R で評価）。資金管理は未実装。
- p 値は両側検定。期待値が負でも小さくなるので、必ず期待値の符号と合わせて読む。
- パラメーターの格子を広げる・条件を足し引きして何度も試すほど、偶然よく見える結果を選ぶ危険が増える。
- 実行時間の目安: 合成データ 11 年分で検証一式が約 1 分、テスト一式が約 40 秒。
